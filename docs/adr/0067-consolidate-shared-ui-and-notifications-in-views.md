# Consolidate shared UI and Notifications in DenViews

Shared visual primitives and the Notification View live in `DenViews`, whose product dependencies are `DenPresentationModels` and `DenDomain`. This supersedes the separate DenDesign module in [ADR 0059](0059-share-presentation-primitives.md). `MotionPreference` is a presentation value in the single Model / VM module; drawing functions remain in Views, keeping Model dependencies independent of display SDKs.

Profile-owned `NotificationOperations` privately retains the existing Store's write capability. The Notification Model receives the authoritative Store and the concrete operation, reads through shared Observation, and receives only the invoking window's existing Board navigation as an injected callback. Clear-confirmation requests go directly back to the Window Model through composition's weak presentation callback, without routing confirmation display through native operations. Shared operations retain no window or presentation callbacks; Runtime event entry points reuse them while preserving existing effect order and Runtime ownership.
